# Floating Voice v0.6.2 — Settings and Target Change Candidate

## Scope

- Split Settings into **App settings**, **Transfer destination**, and **Telegram connection**.
- Show the current verified destination and Telegram authentication readiness in Settings.
- Allow replacing the single transfer destination without logging out or resetting the TDLib session.
- Preserve the current destination if candidate lookup, bot verification, or encrypted persistence fails.
- Stop the floating overlay before destination editing; active recording is retained and not sent.

## Non-goals

- Multiple saved destinations.
- Selecting a default among multiple destinations.
- Choosing a destination per recording/send.

## Build boundary

- Version name: `0.6.2`
- Version code: `12`
- Package: `com.sidequestlab.floatingvoice`
- ABI: `arm64-v8a`
- Android: 10+ (`minSdk 29`, `targetSdk 36`)

## User-operated device validation

1. Update-install v0.6.2 over v0.6.1 without deleting app data.
2. Launch the app and verify Telegram login, current destination, language, size, and color remain.
3. Open Settings and verify the three sections: App settings / Transfer destination / Telegram connection.
4. With the floating button stopped, choose **Change transfer destination**, enter another bot username, and verify it changes without Telegram login.
5. Enter an invalid or non-bot username and verify the previous destination remains active.
6. While candidate verification is in progress, rotate the phone and verify the destination editor and completion path are retained.
7. Start another destination lookup, press Back before it completes, and verify no silent destination replacement or false success appears.
8. Reopen destination editing without submitting and rotate; verify the existing target replay does not announce a completed change.
9. Start the floating button, then choose destination change; confirm the stop dialog and verify editing opens only after the overlay disappears.
10. If recording during step 9, verify the recording is retained and not sent.
11. If an old-destination send is still pending, change destination and send again; verify each result/file is applied only to its own chat.
12. Return home, start the floating button, record once, and verify receipt only at the newly selected destination.
13. Verify API information still requires logout before changing account/API identity, and logout still revokes the session.
14. Check Korean/English, Light/Dark, large text, TalkBack announcements/headings, and system-bar safe areas.

Real-device installation, login, target lookup, recording, and Telegram receipt remain user-operated and are not claimed by build verification.
