# Floating Voice v0.6.3 — Settings Navigation Candidate

## Scope

- Replace the malformed custom gear with a centered standard 24dp settings icon.
- Keep Home free of settings cards and lists.
- Open a compact three-row bottom sheet from the Home gear.
- Route directly to separate pages for **App settings**, **Transfer destination**, and **Telegram connection**.
- Return destination/API editors to their owning settings page.

## Navigation contract

- Home gear → bottom sheet menu only; rotating while it is open closes this transient chooser and keeps Home visible.
- App settings → language, floating-button size, floating-button color.
- Transfer destination → current destination and set/change action only.
- Telegram connection → connection status, API information, logout only.
- Back from any settings page → Home.
- There is no settings landing/dashboard page.

## Build boundary

- Version name: `0.6.3`
- Version code: `13`
- Package: `com.sidequestlab.floatingvoice`
- ABI: `arm64-v8a`
- Android: 10+ (`minSdk 29`, `targetSdk 36`)

## User-operated device validation

1. Update-install v0.6.3 over v0.6.2 without deleting app data.
2. Verify Telegram login, destination, language, floating-button size, and color remain.
3. On Home, verify the gear is visually centered and recognizable at normal and large display/font settings.
4. Tap the gear and verify a bottom sheet with exactly three menu rows appears.
5. Open **App settings** and verify only language, size, and color controls appear; Back returns Home.
6. Open **Transfer destination** and verify only current destination plus set/change action appears.
7. Complete, cancel, rotate, and press Back during destination lookup; verify the v0.6.2 safety behavior remains.
8. Open **Telegram connection** and verify only connection status, API information, and logout appear.
9. Verify API editing returns to Telegram connection and destination editing returns to Transfer destination.
10. Check Korean/English, Light/Dark, 200% font, TalkBack menu labels/pane titles, and system-bar safe areas.

Real-device installation and UI/TalkBack checks remain user-operated and are not claimed by local build verification.
