# V8-01 A52s 시스템 STT 측정 체크리스트

**대상:** `FloatingVoice-v8-01-stt-spike-r2-debug.apk`

**패키지:** `com.sidequestlab.floatingvoice.debug` — 기존 정식 앱과 나란히 설치됨

**범위:** 측정 전용. Telegram 전송·파일 저장·외부 공유 없음. 결과는 앱 메모리에만 있으며 앱 종료 시 사라짐.

## 1. 설치·기본 확인

1. APK를 A52s에 설치하고 `Floating Voice`를 실행한다.
2. 첫 화면 제목이 `V8-01 시스템 STT 측정 (디버그 전용)`인지 확인한다.
3. 마이크 권한은 `말하기 시작`을 처음 누를 때 허용한다.
4. 화면 상단의 일반 인식 가능 여부, 기기 내 인식 가능 여부, 한국어 support 표시를 확인한다.

## 2. 온라인 20문장 측정

1. 네트워크를 켠 상태에서 `일반 시스템 인식`을 선택한다.
2. 화면의 문장을 보고 `말하기 시작` → 문장 발화 → 최종 결과 확인 순서로 진행한다.
3. 틀린 부분이 있으면 `수정한 문장` 칸을 실제 정답 문장으로 고친다.
4. `수정 결과를 메모리에 기록`을 누른 후 `다음`으로 이동한다.
5. 20번 문장까지 반복한다. 생활소음 항목은 평소 TV 소리 정도에서 한 번 측정한다.
6. 앱을 종료하기 전에 하단 20개 요약을 캡처한다.

## 3. 비행기모드 확인

1. 비행기모드를 켜고 앱으로 돌아온다. Wi-Fi도 꺼진 상태로 둔다.
2. `기기 내 인식`이 선택 가능하면 1, 9, 11, 19번 문장을 각각 측정·기록한다.
3. 선택 불가 또는 오류면 화면의 지원 상태와 오류 코드가 보이게 캡처한다. 오류·timeout은 하단 요약에 실패행으로 자동 누적된다. 모델 다운로드나 다른 경로로 임의 전환하지 않는다.
4. 결과 요약에 환경이 `AIRPLANE_MODE`로 기록되는지 확인한다.

## 4. 취소·수명주기

1. 말하는 중 `취소` 후 늦은 결과가 새 결과로 나타나지 않는지 확인한다.
2. 말하는 중 뒤로가기 후 앱을 다시 열었을 때 crash/hang이 없는지 확인한다.
3. 화면 회전 한 번, Home 이동·복귀 한 번 후 다시 인식 가능한지 확인한다.

## 5. 보고할 내용

- 상단 support 정보 캡처 1장
- 온라인 20문장 요약 캡처
- 비행기모드 결과 또는 오류 캡처
- crash/hang 여부
- 체감상 느리거나 반복 실패한 문장 번호

하단 모드별 요약의 `successRate`, `medianLatency`, `medianCorrection`도 함께 확인한다. `medianCorrection`은 최종 원문을 기준문장으로 고치는 데 필요한 문자 거리 ÷ 기준문장 길이의 중앙값이다.

자동검증 PASS는 실제 A52s STT 품질 PASS가 아니다. 위 결과를 받은 뒤에만 V8-01 go/no-go를 결정한다.

## 6. 사용자 결과 — 2026-08-14

**결정:** 형의 명시적 요청에 따라 `V8-01 A52s USER GO/PASS`로 처리한다.

- 온라인 일반 시스템 인식: corpus 화면 `20/20` 도달. 캡처에 표시된 STANDARD 집계는 `attempts=2`, `success=2`, `successRate=100.0%`, `medianLatency=87ms`, `medianCorrection=7.8%`.
- 비행기모드: `기기 내 인식` 및 `비행기모드` 표시 확인. 문장 5에서 `아이 약은`이 `아이야금`으로 인식된 오인이 있었으나 사용자는 전체 품질을 “나쁘지 않다”고 평가하고 PASS를 승인했다.
- 증빙 한계: 캡처에 없는 전체 20개 attempt ledger와 취소·뒤로가기·회전·Home 복귀 결과는 PASS로 추정하지 않는다. 화면의 비행기모드 `수정 문자 거리 0`은 수정 입력이 recognizer 결과 그대로였으므로 기준문장 완전 일치 증거가 아니다.
